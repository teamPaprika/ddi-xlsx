# ddi-xlsx Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Go tool that converts DDI Codebook 2.5 (XML or JSON) to an editable xlsx workbook and back without losing content. It ships as a CLI binary, a Go module and an npm package (wasm) for Node and browsers.

**Architecture:** `ddi` parses XML/JSON into one canonical tree (`*ddi.Node`). It writes that tree as canonical XML or JSON. `internal/schema` is a table generated from the vendored XSD; it supplies JSON repeatability, child sort positions and placement checks. `workbook` maps the tree to four sheets and back: modeled columns plus per-row `attributes`/`xml` cells for everything else, and a `Document` outline for the rest of the document. `cmd/ddi-xlsx` and `wasm/` are thin shells over `workbook.ToXLSX` and `workbook.FromXLSX`.

**Tech Stack:** Go 1.25, `github.com/xuri/excelize/v2` v2.11.0 (the only dependency), stdlib `encoding/xml` and `encoding/json`, `xmllint` in tests, Node 22 for the npm smoke test.

**Spec:** `docs/superpowers/specs/2026-10-26-ddi-xlsx-design.md` (section numbers below refer to it).

- Code comments explain only WHY. No ticket markers, task numbers or doc paths in code.

- Sheet names and column headers are exact (§6): `Variables`, `Categories`, `Groups`, `Document`.
- Canonical XML (§5.5): declaration line `<?xml version="1.0" encoding="UTF-8"?>`, 2-space indent, trailing newline. Text escapes `& < >`. Attribute escapes `& < > "` plus `&#9; &#10; &#13;`.
- Canonical JSON (§5.6): `JSON.stringify(x, null, 2)` byte-compatible, trailing newline.

- [ ] **Step 3: Implement the generator.** Decode the XSD with `encoding/xml` into a generic tree and drop every `xs:annotation` subtree. Then:
  - **Index** named `complexType`s, named `group`s, and global `element name=` → its type. The type is the `type` attribute or an inline `complexType`.
  - **Content of a type**, walked in order:
    - `complexContent/extension`: the base type's particles, then the extension's own particles, numbered after the base's.
    - `complexContent/restriction`: only the restriction's own particles.
    - `sequence`: each child takes the next position.
    - `choice`: every member, including nested sequences, takes the choice's single position.
    - `group ref` in the XSD namespace: inline that group. A `group ref` with an `xhtml:` prefix, or an `xs:any`, sets `anyChild`.
    - `element ref` or `element name`: a particle. A local `element name` also registers that name with its own type, so its children are indexed under that name.
  - **Repeatable:** a particle is repeatable if its own `maxOccurs`, or the `maxOccurs` of any enclosing `sequence`, `choice` or `group ref`, is `unbounded` or greater than 1. `repeatable[name]` is the OR over every occurrence of the name.
  - **Name collisions:** when one element name has several types (local declarations), `children[name]` is the union of their children. On a position conflict, keep the first position seen.
  - **Output:** emit `table.go` with keys sorted.

### Task 6: Workbook writing (tree → xlsx)

**Files:**
- Create: `workbook/columns.go` (headers, split rules), `workbook/write.go`, `workbook/outline.go`
- Test: `workbook/write_test.go`

**Interfaces:**
- Consumes: `ddi.Parse`, `ddi.WriteFragment`, `ddi.FormatAttrs`.
- Produces:
  - `workbook.ToXLSX(input []byte) ([]byte, []string, error)`
  - Exact headers:
    - `Variables`: `ID, name, label, question, questionID, responseDomainType, intrvl, format, formatSchema, formatCategory, notes, attributes, xml`
    - `Categories`: `varID, varName, code, label, missing, freq, attributes, xml`
    - `Groups`: `ID, type, name, label, vars, attributes, xml`
    - `Document`: `level, element, attributes, text, kind`

- **Split rules (§6.1–6.4)**
  - A text column models an element only when the element has **non-empty** text, no attributes, no children and no Raw. Otherwise the element goes to the `xml` cell.
  - `notes`: notes without `\n` go to the column, one per line. All other notes go to `xml`.
  - `qstn`: the qstn's attributes must be a subset of {ID, responseDomainType}, and its children must be exactly one modelable `qstnLit`.
  - `varFormat`: its attributes must be a subset of {type, schema, category}, with no text and no children.
  - `catStat`: modeled only when its attributes are exactly `type="freq"` and it is the only `catStat` of that kind.
  - A Raw `catgry` stays in the var's `xml` cell.
  - Modeled attributes (`ID`, `name`, `intrvl`, `missing`, `type`, `var`) leave the `attributes` cell. The rest keep their input order.
  - Reject these with an error: a `var` or `varGrp` without `ID`, and more than one `dataDscr`.
  - The `Document` outline has one row per node in pre-order. Level is 0 for `codeBook`. The `var` and `varGrp` children of `dataDscr` are skipped. Raw nodes get `kind=xml` and `text=Raw`.
- **Formatting**
  - Every used column gets column style `NumFmt: 49` (text).
  - Row 1 is bold and frozen.
  - `question`, `notes`, `xml` and `text` wrap.
  - The `Document` `element` cell gets an alignment indent equal to its level.
  - Set column widths.
  - Writing any cell longer than 32,767 characters returns an error that names the cell.

### Task 7: Workbook reading (xlsx → tree) and round trips

**Files:**
- Create: `workbook/read.go`, `workbook/merge.go`
- Create: `testdata/archive/nada_like.xml` (synthetic, XSD-valid), `testdata/archive/misordered.xml` (synthetic, var children out of order)
- Create: `testdata/kofac_2024_public/canonical.{xml,json}`, `testdata/kofac_2025_edu/canonical.{xml,json}` (golden, written by the test under `-update`)
- Test: `workbook/read_test.go`, `workbook/roundtrip_test.go`

**Interfaces:**
- Consumes: Task 6 headers and split rules, `ddi.ParseFragment`, `ddi.ParseAttrs`, `ddi.WriteXML`, `ddi.WriteJSON`, `ddi.NormalizeText`, `schema.Position`, `schema.Allowed`.
- Produces: `workbook.FromXLSX(x []byte) (xmlOut, jsonOut []byte, warnings []string, err error)`.

- **Reading rules (§6.5)**
  - Find columns by header name. Unknown headers give one warning per sheet column. A missing column reads as empty.
  - Use displayed cell strings. Convert `\r\n` to `\n`. Pass every text through `NormalizeText`. Skip blank rows.
  - Read `Document` first. Its level-0 row gives the root attributes, whose `xmlns:*` entries are the namespace context for every `xml` cell.
  - Rebuild each `var`, `catgry` and `varGrp`:
    - Attributes: modeled attributes first, in the fixed orders `ID, name, intrvl` / `missing` / `ID, type, var, name`, then the `attributes` cell.
    - Children: column-derived children first, then `Categories` rows for that var in row order, then the `xml` cell's nodes.
    - Stable-sort the children by `schema.Position(parent, child)`. An element with no position takes the position of the item before it in that list, or -1.
    - Do the same at `dataDscr`: merge the outline's `dataDscr` children with the `varGrp` and `var` rows.
  - After rebuilding, group non-contiguous same-name siblings at the first occurrence everywhere, so XML and JSON stay one tree.
- **Errors** (the message starts with the cell address)
  - A duplicate `Variables.ID` or `Groups.ID`.
  - A `Categories.varID` with no variable.
  - A malformed `attributes` or `xml` cell.
  - A `Document` level that jumps by more than 1, or a level-0 row that is missing or not first.
  - A `Variables` row present when `Document` has no `dataDscr` row.
