이 페이지는 범용 변환기의 왕복 동작과 XSD 검사 범위를 설명합니다. 재단 모델 변환에는 다른 보존 규칙을 적용합니다.

## 왕복 보장

1. **고정점**: 이 도구가 만든 XML·JSON을 xlsx로 바꾸고 다시 XML·JSON으로 바꾸면, 결과가 바이트 단위로 같습니다.
2. **무손실**: `var`와 `varGrp`에 ID가 있는 DDI 2.5 입력이면, DDI → xlsx → DDI 결과가 입력과 같은 정규 트리를 가집니다.
   - 예외 1: 주석, PI, DOCTYPE은 경고와 함께 버립니다.
   - 예외 2: 스키마 순서를 어긴 입력에서는 `var`, `catgry`, `varGrp`의 자식이 스키마 순서로 돌아옵니다.
3. **XML과 JSON 일치**: 같은 xlsx에서 나온 XML과 JSON은 같은 트리를 담습니다.
4. **유효성 검사**: 변환 성공은 출력의 XSD 유효성을 보장하지 않습니다. 열 값, `Document` 시트, `xml` 셀을 고쳤으면, 출력 XML을 따로 검사하세요. 도구의 배치 경고는 전체 XSD 검사를 대신하지 않습니다.
5. **Walla 파일**: 설문 도구 Walla가 이 도구의 정규 레이아웃과 JSON 규칙으로 쓴 파일은 1번(고정점)을 보장합니다. 그보다 이전 형식의 Walla 내보내기 파일은 2번(무손실)을 보장합니다.

### 정규 트리

정규 트리는 아래 공백 규칙을 적용하고 속성 순서를 무시한 트리입니다.

- 텍스트 값의 앞뒤 공백과, 둘째 줄부터의 줄 앞 공백을 지웁니다.
- CR을 LF로 바꿉니다.
- 자식 요소 사이에서 줄바꿈이 있는 공백은 들여쓰기로 보고 버립니다.

## 알려진 손실과 변경

아래 경우에는 입력과 출력이 다릅니다.

| 대상 | 결과 |
|---|---|
| 주석, 처리 명령(PI), DOCTYPE | 경고를 내고 버립니다. 원문 보관 요소 안에 있는 것은 원문과 함께 남습니다. |
| 텍스트 안의 들여쓰기 | 텍스트 값의 앞뒤 공백을 지웁니다. 둘째 줄부터는 각 줄의 앞 공백도 지웁니다. 그래서 텍스트 안에 일부러 넣은 들여쓰기는 남지 않습니다. |
| 줄바꿈 문자 | 텍스트 값의 CR(`\r\n`, 단독 `\r`)은 LF로 바뀝니다. 속성 값의 CR은 `&#13;`로 써서 남깁니다. |
| XML 레이아웃 | 출력은 항상 2칸 들여쓰기의 같은 레이아웃입니다. 입력의 공백 배치는 남지 않습니다. |
| XML 1.0에서 금지된 문자 | C0 제어문자(탭, LF, CR은 남김), U+FFFE, U+FFFF, 짝 없는 서로게이트는 출력에서 지웁니다. |
| 스키마 순서를 어긴 입력 | `var`, `catgry`, `varGrp`의 자식은 스키마 순서로 돌아옵니다. 스키마에 없는 요소는 자기 목록 안에서 바로 앞 요소를 따라갑니다. 목록의 맨 앞에 있던 요소는 맨 앞으로 갑니다. |
| `Document` 시트에 직접 넣은 같은 이름의 행 | 같은 부모 아래에서 떨어져 있는 같은 이름의 형제는 처음 나온 자리로 모입니다. 예를 들어 `p, list, p`는 `p, p, list`가 됩니다. 이 규칙은 XML과 JSON이 같은 트리를 담게 합니다. |
| 숫자로 붙여 넣은 값 | 다른 곳에서 숫자로 붙여 넣으면 Excel이 앞의 0을 지웁니다(`01` → `1`). 도구는 표시된 문자열을 읽습니다. 그래서 이 변경은 되돌릴 수 없습니다. |
| `var`, `catgry`, `varGrp`, `dataDscr`의 자식 사이 공백 | 줄바꿈이 없는 공백도 버립니다. 이 네 요소는 요소만 담기 때문입니다. |
| 텍스트만 있는 `catgry` | 한 변수 안에서 텍스트만 있는 `catgry`가 나오면, 그 `catgry`와 뒤의 `catgry`는 모두 그 변수의 `xml` 셀에 들어갑니다. 이 규칙은 범주 순서를 지킵니다. |
| `varGrp/@var`의 변수 이름 | 항목이 변수 ID가 아니고 정확히 한 변수의 `name`과 같으면, 되돌릴 때 그 변수의 ID로 바뀝니다. |

"스키마에 없는 요소의 목록"은 `xml` 셀이거나, `Document` 시트에 있는 `dataDscr`의 자식 행입니다.

{{< callout type="warning" >}}
코드 값을 붙여 넣은 다음에는, 앞의 0이 남아 있는지 확인하세요.
{{< /callout >}}

받지 않는 입력은 [받는 입력](input.md)에 있습니다.

## 스프레드시트 앱

- 공식 지원은 Microsoft Excel뿐입니다.
- Microsoft Excel for Mac (365)에서 텍스트 서식 셀에 300자와 2,000자를 넣어 확인했습니다. 두 경우 모두 `####`이 아니라 내용이 보였습니다.
- LibreOffice와 Google Sheets에서도 동작하도록 만들었습니다. 하지만 테스트하지는 않았습니다.
- Excel 셀 하나에는 32,767자까지 들어갑니다. 이보다 긴 값이 있으면, `to-xlsx`가 셀 주소와 함께 오류를 냅니다.

## 확인한 결과

- 저장소의 fixture 코드북 두 개(`testdata/kofac_*`)는 DDI → xlsx → DDI 왕복 결과가 golden 파일(`canonical.xml`, `canonical.json`)과 바이트 단위로 같습니다.
- `xmllint`가 설치되어 있으면, Go 테스트가 두 코드북을 XML 입력과 JSON 입력으로 모두 확인합니다.
- npm 테스트는 `xmllint`와 관계없이 두 코드북 중 하나를 확인합니다.
- 브라우저(wasm)에서도 같은 두 코드북을 각각 약 0.8–0.9초에 왕복했습니다. 결과는 golden 파일과 바이트 단위로 같았습니다.
