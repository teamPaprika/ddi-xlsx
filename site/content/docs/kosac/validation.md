`check.ValidateXML`은 먼저 ID 형식·중복과 지원하는 참조의 대상을 확인합니다.
`kosac:` 확장이 있으면 `DDI-EXTENSION`으로 반려합니다.
검증기가 있으면 **입력 XML 전체를 그대로** 공식 DDI 2.5 XSD로 한 번 검사합니다.
확장을 제거한 투영 문서의 통과를 표준 문서의 통과로 보고하지 않습니다.

`validator == nil`이면 XSD 검증을 실행하지 않습니다.
이 결과를 표준 적합성 확인으로 사용하지 마세요.
XSD는 `xsd.FS` 전체를 같은 디렉터리에 풀어 상대 경로 import가 작동하게 해야 합니다.
구현은 `cmd/ddi-xlsx/xmllint.go`를 참고하세요.

## 양식과 예제

`template.Blank()`와 `kosac-template`은 재단의 2026-11-17 개정 공식 v4.2.3 빈 양식을 반환합니다.
`template.Write`는 모델의 명시된 버전으로 씁니다. 버전이 없으면 v4.0입니다.
v4.0 항목을 v3.2로 쓰려 하면 유실을 막기 위해 거부합니다.

원본 Excel의 목록 검증 범위에는 빈 구간이 있을 수 있습니다.
Excel 입력 목록만으로 값의 타당성을 판단하지 마세요.
제공 예제, 표준 출력 기준 파일, 과거 형식 fixture의 출처는 [예제 안내](https://github.com/teamPaprika/ddi-xlsx/blob/main/testdata/kosac/README.md)에 있습니다.

## v4.2.3 양식

도구는 `_meta`의 버전으로 양식을 선택합니다. v4.2.3은 01~04 시트를 읽습니다. 05 재코딩 이력은 사용하지 않습니다. 10 미확인 사유와 11 변환 내역이 있으면 Excel로 다시 쓸 때 셀의 표시 값을 보존합니다.

XML·JSON 변환은 규칙판 `20261105-r3`의 재단 프로필을 사용합니다. 파일 ID는 `F01` 형식입니다. 행 식별 키는 `UNIQUE_KEY`를 우선하고, 파일 연결 변수는 양쪽 파일의 변수 ID로 기록합니다. 재단 전용 정보는 표준 DDI의 `notes` 요소에 `KOSAC:` 유형을 붙여 기록합니다. 응답값을 역채점하거나 결측 코드를 추가하지 않습니다.

응답 데이터가 필요한 D01~D11은 코드북 검사 범위 밖입니다. XSD 검사는 CLI에서 xmllint로 실행합니다.

`kosac-check`는 07 시트의 S01~S17을 검사합니다. S09의 미확인 항목은 보고(I)에 표시합니다. 필수값을 확정하지 못한 항목은 사유가 있어도 S01에 남습니다. 내장 표준코드표는 설문용 20261105-v2.3 판입니다. 2026년 학교코드는 같은 판의 NEIS 목록을 사용합니다. 다른 기준연도의 학교코드는 해당 연도의 기관 목록에서 확인하세요.

`SCHOOL.ID` 또는 `SCHOOL.KEDI_ID`의 측정수준이 `해당 없음`이면, S11은 재단 확인이 필요한 표기로 보고(I)에 표시합니다. 코드북 양식과 표준코드표가 학교 식별자의 측정수준을 다르게 안내합니다. 자료형과 코드값은 S11에서 별도로 검사합니다.

v4.2.3 프로필 표시가 있는 XML에서는 재단 notes의 유형·위치(S19)와 범주의 결측 속성(S20)을 검사합니다. 외부 코드의 실제 의미와 원자료 일치 여부는 담당자가 확인합니다.

2024년 표본처럼 복수응답 열의 문항번호가 비어 있으면 같은 파일·설문 구역·저장 방식 안에서 번호가 붙은 변수명의 앞부분을 묶음 이름으로 사용합니다(예: QA22_1, QA22_2). 분할 문항은 배정 변수를 참조하는 조건식에서 찾습니다. UNIVERSE_EXPR가 비어 있으면 RESP_UNIVERSE에 적힌 기계식 조건을 읽습니다.

변환기는 확정된 결측 코드와 라벨을 함께 확인합니다. 뜻이 충돌하면 XML 생성을 중단합니다. v4.2.3 XML은 `ddi.Parse`로 읽습니다. 재단 양식을 다시 쓰려면 원본 Excel 또는 읽어 둔 재단 모델을 사용하세요.
